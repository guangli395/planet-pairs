# 技术选型与数值检查

日期：2026-11-24。已完成首版本地可玩原型，技术为 TypeScript + Vite + Phaser 4.2.1。规则测试与浏览器体验验证已开展；真实 TapTap 接入、广告收益和云端榜单尚未实现。运行方式见项目 README。

历史数值说明：下文模拟使用早期卡数、权重、全家福加翻及清场礼赞规则。当前体力版、等概率发牌及 2026-11-28 的[集齐礼改版](集齐礼玩法改版.md)已替代这些规则，旧通关率不能用于当前版本。

## 技术建议

推荐 TypeScript + Vite + Phaser。Phaser 负责棋盘、卡牌翻面、飞行收集、粒子、音效、触控、缩放与场景切换；规则计算使用独立 TypeScript 模块，广告与排行榜通过平台适配层隔离。首页与弹窗优先保持和游戏一致的美术体系，不为这款小游戏先引入完整后台式 UI 组件库。

Three.js 主要面向 3D 渲染；本项目的卡牌翻转可以通过二维缩放、正背面切换和阴影实现。星球立体感也可用预绘制素材完成，无需先增加 3D 场景、模型和光照。PixiJS 可作为偏重渲染的替代方案，但本项目需要的场景、资源加载、动画、音效等在 Phaser 中更集中。

实查 Phaser 官方仓库 README 提供 Phaser 4 信息及 4.2.1 发布标识；不能继续把之前的 Phaser 3 建议当作当前最新版。开发前先用发布版做最小 TapTap H5 兼容验证，再固定具体版本。官方主分支 skills 面向 v4，必须和最终选定版本核对，不混用 v3 的插件与渲染 API。当前尚未验证本项目在 TapTap 容器的兼容性。

Phaser 内置 tween、粒子、音频、触控与缩放可覆盖首版效果。额外动画库或复杂 UI 插件只在出现明确需求时引入，不把“插件多”当作质量目标。

## 初步数值模拟

脚本：`tools/balance_preview.py`。结果：`docs/概率初步模拟.json`。

每种祝福、每种续局场景各模拟 10,000 局，共 120,000 局；固定种子，可复现。参数使用当前设计：9 种星球，幸运类型权重 0.8、普通权重 1；基础 15 张、启程赠礼 20 张；九宫格补满或耗尽后先横三连、再剩余竖三连、再全盘对碰；幸运奖励立即结算；全家福免费额外卡使用同一加权池；清台返 5，祝福按已确认效果叠加。

模拟跑完整个无限长度挑战直到自然耗尽。因为累计消除张数只增不减，达到 50/60/100 的概率可用于初步估计单次挑战达到相应闯关目标的概率，但不作为每关新开局的连续通关概率。续局组在首次自然耗尽后固定补 10 张，再耗尽结束；如果目标提前达到，后续额外发牌不会改变“是否达到”的结论。广告按成功获得奖励模拟，不涉及填充率。

| 祝福 | 不续局达到 50 | 成功续局 +10 后达到 50 | 不续局平均收集 |
|---|---:|---:|---:|
| 幸运回响 | 11.33% | 89.16% | 34.68 |
| 双重心愿 | 7.18% | 97.09% | 35.19 |
| 启程赠礼 | 4.04% | 99.16% | 38.20 |
| 配对积蓄 | 15.29% | 100.00% | 40.14 |
| 三连余韵 | 0.14% | 60.47% | 26.37 |
| 清场礼赞 | 0.17% | 56.75% | 25.96 |
| 六种等概率平均 | 6.36% | 83.77% | 33.42 |

“100.00%”只表示该组一万次样本全部达到，并非数学保底。所有组均未触及 10,000 轮的安全上限。脚本逐轮检查卡牌数量与发牌资源守恒，未发现断言失败。

结论：目前最明显的设计风险是基础首关通关率很低，且不同祝福强弱差距大；后续每关目标增加 10、初始卡固定，会进一步提高难度。优先用可玩原型验证是否调整起始张数、祝福强度或目标增长方案。本次没有擅自改动用户已确认的数值。

限制：这是简化规则模型而非成品测试；部分视觉和边界尚未实现，真实玩法若有额外机制或生成约束，分布会改变。未测量真实设备帧率、广告收益、实际局长或玩家留存，不用模拟数值作收益承诺。

## 开发前的主要事项

1. 数值：上面的首关难度与祝福强弱需要优先试玩调优。
2. 纯随机体验：手动/自动只改变节奏，玩家技能对结果影响有限。第一版按已确认方向实现，用动作反馈、收集与换肤承载体验，不自行添加指定落点等未确认玩法。
3. 关卡持久化：首页“开始游戏”是继续最高未通关关卡还是从第一关重新挑战，失败后如何重试，尚未明确；建议保存解锁进度、失败只重试本关，待确认。
4. 平台上线：H5 广告开通、真实收益与双榜分别验证。排行榜按用户要求先占位；正式可信成绩和每日次数需要合适的服务端或平台能力。
5. 美术：现有 SVG 是布局稿，正式游戏需要统一卡面、卡背、背景、按钮与音效资源；真实素材与触感比增加技术库更影响最终观感。

下一步建议先制作一屏可玩的九宫格原型，验证已确定的核心循环、动画和难度，再完善首页、无限模式、存档及平台适配。工具调研已经足以支持这一阶段，不必继续为外围细节逐项阻塞原型。

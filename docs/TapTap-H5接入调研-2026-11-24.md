# TapTap H5 接入与排行榜调研

核对日期：2026-11-24。依据当前公开官方文档、由官网链接的官方 MCP 工具说明，以及项目现有代码。本文记录调研与实施建议；尚未登录开发者账号、创建线上榜单、上传或提审游戏。

## 结论与适用路线

本项目可以开始接排行榜。优先使用 TapTap 已提供的榜单服务，无需为了展示名次先自建整套排名数据库。

TapTap 官方明确区分「普通小游戏」与「H5 小游戏」。本项目是 Vite + Phaser 4.2.1，首页、弹窗、翻牌和祝福拆包依赖 HTML/CSS，拆包还使用同源 iframe，应选 **H5 小游戏** 路线。

普通小游戏的引擎适配文档说明其真机运行环境没有 BOM/DOM；这不能用来断言 H5 也不支持网页界面，不据此改成 Cocos 或重写现有动画。H5 平台容器对 iframe、CSS 3D、Web Audio、SVG 纹理和 WebGL 的实际支持，仍需上传测试版本后逐项验证。

官方 H5 MCP 说明可以上传 `dist` 构建目录。官方发布的 `@taptap/instant-games-open-mcp@1.24.14` 上传实现检查入口 `index.html`、压缩构建目录、提交游戏包及横竖屏配置。本项目已有 `dist/index.html`，Vite 也已使用相对资源路径 `base: './'`。这表示构建形式符合接入方向，不表示已通过平台审核或真机兼容测试。

## 官方说明及需要区分的范围

| 事项 | 已核对事实 | 本项目行动 |
| --- | --- | --- |
| H5 支持 | 官方介绍同时支持普通小游戏和 H5 小游戏；MCP 指南明确面向 H5，提供上传、排行榜等能力 | 保留现有技术栈，以 H5 应用联调 |
| 开发者身份 | 认证开发者支持个人、企业；仅「注册开发者」创建的游戏不能提审、不会面向玩家展示 | 先核对账号认证与选定应用，不能假定必须注册公司 |
| 排行榜 | `tap.getLeaderboardManager()` 获取管理器；支持提交、列表、我的名次和官方面板；支持永久、日、周、月榜及最高分计算 | 首版创建两份永久榜，按最高分保留 |
| 运行环境 | 官方称 `tap` 由平台运行时提供，不需要另装排行榜 SDK；低版本需做能力检测 | 本地浏览器继续展示本机纪录；平台环境调用真实能力，不能假装已有联网名次 |
| 好友榜 | 好友相关调用需要后台隐私声明及用户授权 | 首版先做全服榜，后续有需求再接好友榜 |
| H5 广告 | H5 专用广告指南要求账号认证、完整财务主体信息，并在「商店 → 小游戏广告」申请开通 | 走 H5 广告入口；不要直接套用普通小游戏的 Dirichlet 接入流程 |
| 激励广告 | 用户主动触发；看完才发奖励；加载失败不能卡住游戏 | 替换 `demoAd`，覆盖完成、取消、失败、重复回调，保留原有计次隔离 |
| 宣发物料 | 公共小游戏指引要求简介、宣传图、实机截图及录屏 | 先准备游戏图标、1920×1080 横图、1440×1440 方图、至少三张实机截图及竖屏录屏；最终按 H5 后台字段提交 |
| 隐私与素材 | 审核规范要求必要的数据授权、用户数据通过 HTTPS 传输及合法素材授权 | 排行榜按平台授权展示昵称/头像，保留开源许可，不采集无关信息 |

### 不直接套给 H5 的条件

官方的「小游戏前置备案」页面明确说主要面向 **普通小游戏**。它要求开发者认证、包体、软件著作权人、游戏内容说明及负责人核验，材料无误时预计 20 个工作日内完成。这个时长与整套材料不能直接当作 H5 的已确认要求。

「创建小游戏」页写不涉及内购的小游戏无需提交版号；不能将此扩展成 H5 无需任何审核或资质。我们目前没有充值功能，H5 应用实际需要的备案、权属材料与发布权限，应在选定应用后的后台核对；公开文档尚不足以确认这个账号的具体要求。

公开文档中的包体限制存在冲突：「创建小游戏」写首包不超过 `60M+`，「小游戏审核规范」写 `20MB` 以下。这两处也没有清晰给出 H5 专属限额。因此不把其中任一数字作为本项目 H5 的确定上限，以上传入口的实际校验为准。当前 `dist` 共 1,670,690 字节，约 1.59 MiB，是未压缩文件总量，不能与下载流量或平台 ZIP 限额混为一谈。

## 第一版排行榜方案（建议）

| 榜单 | 上传值 | 后台规则 | 页面 |
| --- | --- | --- | --- |
| 闯关榜 | 实际成功通过的最高关卡 | 整数、降序、保留最高分、永久 | 首页前三名；完整榜单；我的名次及最高关卡 |
| 无限榜 | 无限模式单局已结算的收集星球数 | 整数、降序、保留最高分、永久 | 首页前三名；完整榜单；我的名次及最高成绩 |

首版保留现有两榜入口，不同时加很多分类。后续可以加无限周榜，让新玩家有机会参与。

接入点与边界：

1. 封装平台适配层，能力检测后获取管理器；处理未配置、平台不支持、超时及失败。普通浏览器仍可正常游玩。
2. 在后台创建两榜，使用客户端字符串榜单 ID，而不是后台数字数据库 ID；开发期配置测试白名单。
3. 闯关只在真实通关后更新最高关卡。无限模式上传本局已结算成绩；广告续局后成绩提高再更新。同一局重试不得按累计相加，提交要去重。
4. 不把旧的 `localStorage` 纪录直接当作可信线上成绩。正式规则版本开始产生新成绩，保留本机纪录的用途。
5. 首页获取真实前三；弹窗获取榜单列表和我的名次。无成绩显示空位，网络失败显示简短重试入口，不编造玩家或名次。
6. 账号成绩与正在进行的对局分开处理：不重新引入用户已要求去掉的对局自动存档。中途结束仍清空本局，取消退出仍留在当前页面。
7. 官方面板可以用于第一轮联调；现有星际风格页面可通过数据接口接入。平台的同分排序以实际榜单规则为准，不额外声称支持自定义多字段排序。

真正联调所需：选定的 TapTap H5 应用、开发者操作权限、两份榜单的客户端 ID，以及能在 TapTap App 中运行的测试版本。广告另需后台开通及对应配置。

## 成绩可信度与公平性（工程建议）

平台提供排名存储与查询，不代表会验证我们的自定义玩法。当前 `rules.ts` 的抽牌、`main.ts` 的隐藏卡包触发、广告模拟奖励及纪录都是客户端计算，直接提交任意客户端数值无法实现可靠防作弊。

先完成平台榜单联调；正式开放竞争前，再设计成绩校验服务：校验开局档位、祝福、规则版本、抽牌与返卡、广告续局、隐藏切包奖励及重复提交。规则模块已与画面分离，适合复用进行结果核验；若采用随机种子及操作重放，需同时校验开局与奖励来源，不能只信任客户端上传的最终分数。自建校验服务是针对本游戏的建议，不是使用官方基础榜单的强制前提。

20/30/40/50 起始牌、祝福选择、续局会影响成绩。第一版可明确采用允许这些玩法的综合榜，并记录对局条件用于排查异常；以后需要公平挑战时，再设计固定条件的独立榜，不擅自修改现在已确认的玩法。

## 优化优先级（建议）

1. **平台闭环**：H5 真机兼容验证 → 两榜与身份联调 → 真实广告 → 可信成绩。优先打通真实使用链路。
2. **手机流畅度与异常恢复**：检查拆包、六卡翻面、连续发牌的帧率，以及广告返回、切后台、锁屏、断网、窄屏与安全区。依据实测增加低性能设备动效档位。
3. **首次加载**：当前主 JS 约 1.42 MB，主要含 Phaser。可以考虑按需加载棋盘模块、预热拆包资源；先测首屏耗时，再决定是否拆分。
4. **重复游玩的负担**：保留第一次完整拆包，后续可以考虑玩家主动跳过演出的按钮；只跳动画，不改变随机、免费翻一张及广告任选规则。
5. **新手与数值**：只加一次短操作引导；按当前九种等概率、20/30/40/50 档与隐藏包规则重新模拟局长、祝福差异及广告使用情况。旧数值文档中的 15 张、加权抽牌模拟不能当作现在版本的结论。

# 新增皮肤接入指南

更新日期：2026-11-24。适用于 `D:\youxi` 当前版本，现有参考为「经典宇宙」「萝卜宇宙」「奶茶宇宙」「奶娃宇宙」。后续新增皮肤优先按本文接入；已有开发经过及截图见[宇宙换肤验收](宇宙换肤验收.md)、[奶茶宇宙设计与验收](奶茶宇宙设计与验收.md)和[奶娃宇宙设计与验收](奶娃宇宙设计与验收.md)。

## 一、沿用的产品约定

- 皮肤称为「宇宙」，在首页免费切换；切换入口由注册表自动生成。
- 每套皮肤提供 **9 种角色**，共用规则编号 `0～8`。只改变外观、名称与界面表现，概率仍为各 `1/9`，配对、三连、祝福和奖励规则共用。
- 关卡、体力、广告计次和个人纪录共用，不按皮肤另建存档或榜单。
- 仅在首页切换，记住外观偏好；不增加对局内换肤，不恢复已结束或刷新前的对局。
- 更换皮肤后，首页主图、卡片、祝福包、隐藏包和动画等所有角色展示位置都跟随更换。
- 保持页面简洁：标题、必要提示和按钮即可，避免增加说明小字或装饰性英文。

## 二、最快的接入步骤

1. 确定皮肤 ID、名称、主角、9 种角色及界面基调，先做九宫格素材预览，确认小尺寸下能分辨。
2. 在 `public/assets/<皮肤ID>/` 放入素材，保留源文件或生成脚本。
3. 在 `src/themes.ts` 的 `UNIVERSES` 数组中复制一份最接近的新条目并追加：深色参考 `classic`，暖色参考 `carrot`，红白店铺风格参考 `milktea`，深色鎏金与位图半身像参考 `naiwa`。替换 ID、名称、角色、素材、文案和配色，保留已有条目；`classic` 保持第一项，当前未知 ID 的回退会取数组第一项。
4. 使用独立预览检查完整流程；根据实际差异补充主页面和祝福 iframe 的样式。
5. 运行测试、构建，检查普通入口的切换记忆和旧主题回归，再记录验收结果与截图。

通常无需复制 `main.ts`、`board.ts` 或规则模块。若需求涉及新角色数量、新玩法、独立祝福插画或新的界面基调，先按后文的扩展边界调整接口。

## 三、素材准备

| 素材 | 数量与当前参考尺寸 | 注意事项 |
| --- | --- | --- |
| 角色图 | 必须 9 张；萝卜版为 320×320 SVG | 正方形画布、透明背景，统一主体大小、留白、光照与朝向；图片内不加角色名，名称由界面绘制 |
| 统一卡背 | 必须 1 张；萝卜版为 210×270 | 用于祝福卡背、发牌、翻牌、牌堆及奖励飞卡；同时检查长卡和方形翻牌的显示比例，主体不要贴边 |
| 隐藏卡包 | 必须 1 张；萝卜版为 240×330 | 独立的切包挑战封面，采用有封口、折边与袋身的包装外观；保持透明外轮廓，图中文字若含主题名也要同步更新。实际切片及表面切口直接使用此图，SVG 内嵌位图需用 data URI，不能依赖 SVG 外链图片 |
| 首页主角 | 从 9 张角色中选 1 张 | 当前通过 `hero` 指定编号，无需额外交一张独立首页大图 |
| 六张祝福插画 | 当前复用角色图 | 自动取当前主题的部分角色；暂没有独立的六图配置字段，具体映射见下一节 |
| 九宫格预览图 | 建议 1 张，非运行必需 | 用于比较全部角色的辨识度；`preview.svg` 不会自动成为切换弹窗背景 |

建议目录：

```text
public/assets/forest/
  character-0.svg
  character-1.svg
  ...
  character-8.svg
  cardback.svg
  hidden-pack.svg
  preview.svg
```

`forest` 仅为示例 ID，并非已加入的皮肤。角色素材可采用透明 PNG，奶娃版为 384×384 RGBA；资源测试已检查 PNG 文件头、尺寸与透明通道，并继续检查 SVG 的 `viewBox`。若使用 WebP 等其他格式，先补对应检查。位图应提供足够分辨率以适配高像素密度屏幕，先检查约 94×94 的棋盘角色和约 36×36 的缩略图是否清楚，避免仅看大图。透明素材还需在深、浅背景下检查白边与压缩残影，不能只看白色画板。

棋盘已适配高分屏：SVG 以 384×384 栅格化，角色位图建议至少 384×384；卡框、角色与名称会预合成为 324×324 卡面，翻牌和落定共用。不要另做低清棋盘缩略图。可用 `?previewBoard=1&previewUniverse=forest&previewBoardDpr=3` 在开发服务检查九张卡与三倍像素密度，详见[按钮音效与棋盘清晰度](按钮音效与棋盘清晰度验收.md)。

辨识度优先于颜色数量：红/粉、黄/橙曾出现过过于接近的问题。除了色相，也应拉开明暗、饱和度；必要时用轮廓或局部细节辅助识别。同一套角色在九宫格里应有相近的视觉大小。

## 四、注册表字段与实际限制

配置入口：[src/themes.ts](../src/themes.ts) 中的 `UniverseTheme` 与 `UNIVERSES`。

| 字段 | 新皮肤需要填写的内容 |
| --- | --- |
| `id` | 唯一、稳定的英文小写 ID，建议用短横线分词；用于偏好保存和纹理命名，发布后不要随意改名或与旧皮肤重复 |
| `name` | 切换弹窗显示的名称，如「森林宇宙」 |
| `palette` | 当前仅支持 `night` / `warm`；它还影响棋盘与祝福卡的视觉分支，不只是背景色 |
| `hero` | 主角在 `characters` 中的下标，范围 `0～8` |
| `material` | 可选；`gilded` 启用棋盘金属压边与 iframe 深色鎏金卡框，仍需补本主题 CSS |
| `blessingCharacters` | 可选；按六种祝福顺序指定角色下标，必须 6 项且在 `0～8` 内；同时传给拆包和主页面祝福介绍 |
| `characters` | 必须 9 项，每项包含 `name`、`color`、`image`；下标对应共用规则编号，名称和图片应各自可区分 |
| `cardBack` / `hiddenPack` | 当前主题的统一卡背和隐藏包路径 |
| `copy` | 完整填写 `title`、`subtitle`、`blessing`、`subject`、`unit`、`journey`、`pack`、`welcome`、`clear`、`desktop` |
| `colors` | 主页面 CSS 变量，不含 `--` 前缀；选择暖色时也要完整保留并调整 `warm-*` 变量 |
| `board` | 棋盘槽位、边框、圆点、三段卡面渐变 `face`、卡片侧边 `side`、名称文字 `ink` |
| `pack` | 祝福包材质色 `color`、高光 `highlight`、阴影 `shadow`、正面底 `face`、文字 `ink` |

填写时注意：

- 资源路径使用 `./assets/forest/character-0.svg` 这样的相对 URL；文件实际放在 `public/assets/forest/`。不要写成 `./public/assets/...`、Windows 绝对路径或带反斜线的路径，也不要假定部署在站点根目录。
- `characters[].color`、`board` 中的颜色使用 **六位十六进制 `#RRGGBB`**。现有代码会拼接透明度后缀或解析十六进制，不能直接替换为 `rgb()`、`var()` 或三位简写。`pack` 中的颜色也建议统一使用该格式。
- `copy.title` 只填标题前半部分，如「森林」；界面会追加「翻翻碰」。`subject` 用于「幸运××」等文案，`unit` 用于成绩单位。`desktop` 可按现有写法使用 `<br>` 换行。
- 角色名应短，当前棋盘名称字号约 10px；长名字可能溢出。正文应检查替换后的语句是否自然。
- 发牌、结算的主要过程提示已改用 `copy.subject`。新加界面时仍应检查初始模板及展示文案中的固定「星球」字样，不要批量替换规则中的 `PLANETS` 或数字编号。

### 祝福插画的当前映射

祝福的 ID、顺序与效果由 `src/rules.ts` 的 `BLESSINGS` 决定，不因换肤改变。目前 `public/prism-blessing/cards-config.js` 按祝福顺序选图：

- `warm` 使用角色下标 `0、1、2、3、4、5`。
- `night` 使用角色下标 `3、2、4、0、7、6`。
- 若填写 `blessingCharacters`，拆包正面优先使用该映射；奶娃版为 `0、1、2、3、4、5`。
- 主页面「祝福介绍」优先使用 `blessingCharacters`，未填写时仍用角色下标 `0～5`，保留旧主题行为。

因此目前复用九种角色即可生成六张祝福卡。若未来要求每种祝福配独立插画，或首页使用独立主视觉，应新增明确的主题字段，并同步修改主页面、`packAppearance()`、iframe 配置和测试，不能只把新图片放进目录就期待自动使用。

## 五、页面与 iframe 要一起处理

| 文件 | 职责与新增皮肤时的检查点 |
| --- | --- |
| `src/themes.ts` | 主题注册、资源路径、文案与颜色；`packAppearance()` 将父页面资源转为绝对 URL，并将颜色变量传给 iframe |
| `src/main.ts` | 首页及切换列表、准备流程、玩法介绍、隐藏切包、收集和奖励返卡；新增展示图继续读取当前主题 |
| `src/themes.css` | 主页面配色、弹窗、奖励文字和光效；已有暖色覆盖不能遗漏 |
| `src/board.ts` | 按主题 ID 加载角色、生成卡面、合成翻牌图；纹理键中带主题 ID，切换时清理棋盘与合成图缓存 |
| `src/hidden-slices.ts` / `src/hidden-pack.ts` / `src/hidden-pack.css` | 同一组刀线多边形用于计数、原图裁切与最终散落；表面切口受图片透明轮廓限制，刀光只短暂出现。新皮肤直接复用，不再叠加永久划痕或预制四等分碎片 |
| `src/blessing-pack.ts` | 父页面向拆包 iframe 传递主题；保持统一传递入口 |
| `public/prism-blessing/bridge.js` | iframe 接收主题、卡背、盲翻侧边与光晕 |
| `public/prism-blessing/cards-config.js` | 祝福包主角、材质、六张正面角色与颜色 |
| `public/prism-blessing/integration.css` | iframe 内的背景、文字、选中态、盲翻边框和阴影；父页面 CSS 不会自动进入 iframe |
| `src/store.ts` | 保存皮肤 ID，未知 ID 回退经典宇宙；沿用当前存储键和永久进度，不另建皮肤存档 |
| `tests/themes.test.ts` | 遍历全部注册皮肤检查资源，同时验证路径、偏好保存和回退行为 |

当前仍有一些暖色按钮渐变、装饰和 iframe 卡框颜色直接写在 CSS/配置中。**只改 `colors` 不保证整套界面全部变成新配色。** 如果只是换角色并沿用暖色布局，可直接复用；如果需要明显不同的界面色调，应检查这些固定色并补变量或专属覆盖。奶茶宇宙提供了 `tea-*` 变量与专属覆盖的实例，颜色变量也会传入 iframe，但新主题需要自己声明并使用对应变量。

新增专属样式时，主页面用 `:root[data-universe='forest'] ...`，iframe 内用 `body[data-universe='forest'] ...`，避免影响现有皮肤。若要增加第三种 `palette`，需同时扩展类型、主页面 CSS、切换预览样式、棋盘和 iframe 中现有的暖/暗分支，不能只新增一个字符串。

不要为换肤复制上游拆包动画引擎或删减粒子、撕裂、出卡、翻面效果。所有皮肤沿用现有演出与音效开关；保留开源许可文件。

拆包彩带由 `src/blessing-pack.ts` 将同源 iframe 中实际运动的 SVG 挂载到父页面的整页特效层，原引擎继续更新它；`ribbonOverflow` 同步顶部和两侧可延伸的范围。新增皮肤继续复用此机制，不把彩带重新限制在卡包窗口内。调整准备页布局时检查坐标、缩放及退出清理；特效层保持 `pointer-events:none`，标题与操作按钮置于其上方。

## 六、最容易遗漏的地方

- **盲翻不能泄露内容。** 六张未翻开的祝福卡必须拥有相同背图、侧边、光晕、阴影和悬停表现；正面可见后才显示各自颜色。已有统一处理在 `integration.css`，不要被新样式覆盖。
- **浅色提示不能继承深色重影。** 检查普通幸运、对碰、六种祝福、清台提示的背景、字色、文字阴影、图标滤镜及粒子颜色；曾出现文字重影与黑色光晕问题。
- **所有皮肤都使用相同的大卡片。** 列表固定两列，奇数个时最后一张保持标准尺寸，不跨列、不改成横向小卡。弹窗限制在可用高度内，标题与关闭按钮固定，皮肤列表超高时内部滚动并显示细滚动条；打开弹窗时锁定底层页面，关闭后恢复。新增更多皮肤直接追加注册表，并检查列表底部可滚动到达。列表缩略图当前取 `hero` 以及角色 `1、3、5`。
- **素材热更新后要完整刷新。** 棋盘启动时会预加载所有主题角色，卡面纹理按主题 ID 缓存。替换素材或颜色后重载检查，避免旧缓存造成误判；新主题也必须具有独立 ID。
- **主题多了会增加启动加载量。** 当前每新增一套会多预加载 9 张角色图，正式位图需压缩并检查加载耗时；主题较多时再评估按需加载。
- **保留美术源。** 萝卜素材由 `tools/generate-carrot-assets.mjs` 生成；只修改输出 SVG，重新运行脚本会被覆盖。新皮肤若采用生成脚本，也要同步保存源配置和输出资源。
- **新增资源检查不等于已做加载失败回退。** 当前未知皮肤 ID 可以回退，但单张图片缺失并没有统一的占位恢复机制，需通过资源检查和页面加载验收及时发现。

## 七、验收流程

### 开发预览

先运行 `npm.cmd run dev`，将以下 URL 中的 `forest` 换成已经注册的真实 ID：

| 入口 | 检查内容 |
| --- | --- |
| `http://localhost:5173/?previewUniverse=forest` | 独立首页，从这里进入完整开局和实际游戏 |
| `http://localhost:5173/?previewUniverse=forest&previewBlessing=1` | 直接进入该皮肤的拆包准备流程 |
| `http://localhost:5173/?previewUniverse=forest&previewHidden=1` | 隐藏切包 |
| `http://localhost:5173/?previewUniverse=forest&previewSettlement=1` | 三连、三个对碰、清台连续结算；最终收集 9、剩余 22 张 |
| `http://localhost:5173/?previewUniverse=forest&previewOpening=echo&previewCards=20` | 新开局星星到牌堆的入堆动画；`previewOpening` 可用六种祝福 ID，`previewCards` 可用 20/30/40/50，赠礼额外 +20 |
| `http://localhost:5173/tools/blessing-preview.html?theme=forest` | 普通幸运、对碰和六种祝福提示的独立预览 |

以上入口不读写玩家进度。`previewUniverse`、`previewBlessing`、`previewHidden`、`previewSettlement`、`previewOpening` 及配套的 `previewCards` 参数只在开发模式生效，正式构建要从普通首页切换验收。注意 `tools/blessing-pack-preview.html` 目前默认经典主题，没有主题查询参数；检查新主题的拆包请使用上表中的主页面入口。

### 每套新皮肤都要勾选

- [ ] 首页主角、桌面装饰、游戏标题、切换预览、使用中状态、成绩单位和玩法说明正确。
- [ ] 九种角色在幸运选择和实际棋盘上都清楚可辨，图片不裁切、名称不溢出。
- [ ] 祝福包封面、主角、六张正面插画均属于新皮肤；滑动拆包、出卡和翻面效果完整。
- [ ] 开包后六张均为统一背面；免费仅翻一张，剩余锁定；点击广告任选直接解锁其余卡，可重新选择并继续。
- [ ] 检查双重心愿选择两种幸运角色，以及祝福介绍中的图文。
- [ ] 起始牌预览、下方卡堆、发牌卡背、棋盘翻面、全家福额外卡均正确。
- [ ] 首次进入棋盘，所有祝福均有星星到发牌处的起始牌入堆动画；数量从 0 增长到最终总数，赠礼额外 +20 正确，图像解码完成后再飞行；入堆声音跟随静音开关，继续对局不重复播放。
- [ ] 普通幸运、六种祝福、对碰、三连、清台提示清楚，明暗与当前主题匹配。
- [ ] 上一组到达进度区域后，下一组立即开始；返卡并行，成绩不回跳、剩余数正确、结束后无残留动画。
- [ ] 隐藏包和切包背景正确；有铝箔包装、封口与折边的外观。一刀两片、交叉四片的画面与计数一致，切口贴在包身内，刀光及时消失；结束按实际碎片形状散落，奖励返牌正常。
- [ ] 返回首页取消时保留页面；确认时清空本局，不因换肤重新引入自动存档。
- [ ] 从普通入口新皮肤→经典→萝卜→奶茶→新皮肤往返，卡图及配色不混用；切换不扣体力，永久纪录共用。
- [ ] 普通入口刷新后记住新皮肤；检查缺少或未知皮肤 ID 时仍能回退经典，保留玩家进度。
- [ ] 至少检查 390×844、320×640 和桌面宽屏；按钮可触达、弹窗可滚动、没有横向溢出。
- [ ] 检查静音开关及系统减少动态效果设置，换肤不重新加入落地沙沙声。
